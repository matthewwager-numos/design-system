# IconChart

An icon-multiples ("pictogram"/"isotype") chart — repeats one icon to show quantity, matching Figma's three reference layouts (`orientation="horizontal"` rows, `"vertical"` columns, `"wrap"` a single wrapping run) plus a fourth `variant="percentage"` that divides a fixed grid across up to ~5 categories proportionally — a pie-chart/treemap-style "share of a whole" reading, rendered in icons instead of area.

<Controls />

## When to use

- A quick, literal "count of things" reading where the reader can roughly tally icons — headcount by team, units shipped, seats filled.
- `"percentage"` for a small number of categories' share of one whole (headcount by department, storage by file type) where a round grid (10×10 by default) is a familiar, countable stand-in for a pie chart.

## When NOT to use

- Precise value comparison, or values too large to render as individual icons — use `<BarChart>` instead; nobody is meant to count past a few dozen icons.
- Continuous trends — use `<LineChart>`/`<AreaChart>`.

## Implementation

```tsx
import { IconChart } from "@numosai/ui";
import { User } from "lucide-react";
import "@numosai/ui/styles.css"; // once, at your app entry

<IconChart
  icon={User}
  unitValue={10}
  unitLabel={(unitValue) => `= ${unitValue} people`}
  data={[
    { label: "Sales", value: 70 },
    { label: "Support", value: 50 },
    { label: "Engineering", value: 40 },
    { label: "Executive", value: 30 },
    { label: "HR", value: 20 },
  ]}
/>
```

## `icon` is any lucide-react component

Not a rendered element — a component reference (`icon={User}`, not `icon={<User />}`), the same convention Figma's own instance-swap uses. `IconChart` renders it many times over, computing `color`/`fill`/`size` per icon itself; any component accepting those same props (a custom SVG wrapper included) works as a drop-in replacement.

## `unitValue` — one icon per N

Each datum's `value` is divided by `unitValue` (default 1, i.e. `value` *is* the icon count) and rounded to the nearest whole icon — the `unitLabel` caption (rendered with the same icon, muted) is what tells the reader that ratio, matching Figma's own "= 10 people" example. Pass a function rather than a plain string — it receives the current `unitValue` so the caption's number can never drift out of sync with it: `unitLabel={(unitValue) => `= ${unitValue} people`}`. A plain node still works for a caption with no such number.

In `"percentage"`, the icon count is always the fixed grid total (`columns × columns`), not `value ÷ unitValue` — `unitValue`/`unitLabel` there are purely descriptive (e.g. "≈ 2 people per icon"), for a caption above the grid.

## Orientation

`"vertical"` gives each datum its own bottom-aligned column instead of a row — otherwise identical.

`gap` (px, default 0) is the space between icons — a negative value overlaps them instead, e.g. a stacked-coin look for a currency icon:

By default `"wrap"` breaks lines wherever the browser runs out of container width — pass `maxPerLine` to break at a fixed count instead, laid out as a deterministic grid:

## A single category — `color` instead of `data[0].color`

For a chart with just one category, `color` sets that one icon's color directly, rather than reaching into `data[0].color` — a per-datum `color` still wins if both are set:

<Canvas of={ChartIconStories.SingleCategoryColor} />

## `iconSize` is 16 or 24

Lucide's icons are drawn on a 16 or 24px grid — anything else looks slightly off, so `iconSize` only accepts those two values (default 16) rather than an arbitrary number.

## The legend shows each category's value

Hovering or focusing any icon already surfaces its value in a tooltip — the legend (or key) below the chart shows it too, so the count is visible without interaction, and updates automatically whenever `data` does.

## Wrap: one run, identified by color

`orientation="wrap"` pours every datum's icons into a single wrapping run in sequence instead of separate rows/columns — there's no longer a row/column position to identify which icons belong to which datum, so `showLegend` defaults to `true` here (`false` for `"horizontal"`/`"vertical"`, where each row/column already carries its own label).

<Canvas of={ChartIconStories.Wrap} />

## Fill defaults to 50% of the stroke color

`lucide-react` icons are stroke-only (`fill="none"`) by default — `fill` here defaults to a 50%-opacity version of each icon's own resolved stroke color instead (via the same `chartColorMuted` `color-mix` every other chart in this library already uses for its own dimmed/hover state), giving a softer duotone look confirmed from Figma (Figma's own icon instances have a real fill set, not just a stroke). Pass `fill="none"` for a plain outline, or a fixed color to use the same fill everywhere regardless of value:

<Canvas of={ChartIconStories.CustomFill} />

## Percentage of a whole

`variant="percentage"` takes `data` (the same shape as `"categories"`) instead of a single value, and divides a fixed `columns × columns` grid (default 10×10 = 100 icons) across it proportionally — each datum's own share of the whole, rounded to a whole number of icons via the largest-remainder method (so shares always add back up to the full grid, the same rounding problem real-world seat-apportionment methods solve). Icons fill in sequence, one datum's share at a time, the same reading order a pie chart's slices or a treemap's tiles would give you. `showLegend` defaults to `true` here too — same reasoning as `"wrap"`, color is the only thing identifying a datum.

The grid is the widest thing in this variant, so the caption and legend are centered underneath it (rather than the left alignment `"categories"` uses) instead of each other:

## Colors

Both variants default to the five-color `--chart-1`…`--chart-5` palette assigned by index — pass `color` on a datum to override it.

## Accessibility

- Each icon is `tabIndex`-focusable with an `aria-label` describing its own datum — hovering or focusing any icon belonging to it shows the same tooltip, since a whole run (or, in `"percentage"`, a whole share) is one hoverable unit, the same convention `<BarChart>`/`<DonutChart>` use for a whole bar/segment.
