# BarChart

A vertical or horizontal bar chart — matches Figma's Chart component's colors, typography, and grid/baseline treatment exactly. `orientation="horizontal"` is the same chart transposed, not a separate implementation. Three variants: `"single"` (default, one bar per category), `"clustered"` (several series' bars side by side per category), and `"stacked"` (several series' segments stacked into one bar per category).

## When to use

- Comparing a handful of discrete categories against each other (revenue by region, count by status).
- `orientation="horizontal"` when category labels are long — a vertical chart's rotated or truncated labels are harder to read than a horizontal one's full-width row.

## When NOT to use

- A continuous trend over time — use `<LineChart>`.
- Part-to-whole composition of a single total — use `<DonutChart>`.

## Implementation

```tsx
import { BarChart } from "@numosai/ui";
import "@numosai/ui/styles.css"; // once, at your app entry

<BarChart
  data={[
    { label: "First", value: 58 },
    { label: "Second", value: 73 },
    { label: "Third", value: 94 },
    { label: "Fourth", value: 73 },
    { label: "Fifth", value: 96 },
  ]}
/>
```

## Legend defaults off for `variant="single"`

The default variant is always one bar per labeled category. With `showCategoryLabels` on — the normal case — every bar already carries its own label, so a legend alongside it would just repeat the same names in a second place. It only earns its keep when there's no room for those per-bar labels in the first place:

## Clustered and stacked

`variant="clustered"`/`variant="stacked"` group several *series* under one shared category instead — several colors sharing one axis label (e.g. a month), each color meaning something different. That's the actual scenario a legend is for: the axis identifies the category, color identifies the series, and neither one substitutes for the other — so both variants default `showLegend` to `true`. Their `data` shape is different from the single-bar variant's own: an array of `{ category, values }` (one shared axis label plus a value per series), alongside a `series` array (`{ key, label, color? }`) naming and coloring each one consistently across every category.

Vertical-only for now — Figma's own reference only designed these two variants that way.

```tsx
<BarChart
  variant="clustered" // or "stacked"
  series={[
    { key: "first", label: "First" },
    { key: "second", label: "Second" },
  ]}
  data={[
    { category: "Jan", values: { first: 58, second: 73 } },
    { category: "Feb", values: { first: 40, second: 45 } },
  ]}
/>
```

## Colors

Bars default to the five-color `--chart-1`…`--chart-5` palette (Figma's own "Charts/First"–"Charts/Fifth"), assigned by index — pass `color` on a datum to override it.

## Ticks are computed, not literal

Figma's own grid rows show static `"00"` placeholder text at each end. Here, every tick is a real value derived from `data`'s max — `gridLineCount` (default 5) controls how many divisions, not what they say.

## Accessibility

- The bars and grid are `aria-hidden` — a bar chart's visual encoding doesn't have a meaningful DOM/AX fallback of its own; pair it with a visually-hidden data table or summary if the underlying data needs to reach assistive tech.
- Legend and axis/category text render as real, readable text (not baked into an image), so zoom and text-scaling work normally.
