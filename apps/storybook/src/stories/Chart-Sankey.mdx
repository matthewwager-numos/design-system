# SankeyChart

A flow diagram — matches Figma's color palette and stage-label row, but Figma's own ribbons are 71 flattened SVG vector fragments, not real flow data. This lays out `nodes`/`links` from first principles: nodes stacked within their `stage` column sized by throughput, links drawn as smooth ribbons sized by `value` and stacked in input order along each endpoint.

<Primary />

<Controls />

## When to use

- Visualizing how a quantity splits and flows across a sequence of stages — funnel drop-off, budget allocation across categories, traffic sources into outcomes.

## When NOT to use

- A single stage of part-to-whole composition — use `<DonutChart>`.
- Comparing magnitudes with no flow between them — use `<BarChart>`.

## Implementation

Every node declares which column (`stage`) it belongs to — an arbitrary link graph has no single correct column ordering to derive automatically, so it isn't inferred:

```tsx
import { SankeyChart } from "@numosai/ui";
import "@numosai/ui/styles.css"; // once, at your app entry

<SankeyChart
  nodes={[
    { id: "visits", stage: 0 },
    { id: "signups", stage: 1 },
    { id: "bounced", stage: 1 },
    { id: "customers", stage: 2 },
    { id: "churned", stage: 2 },
  ]}
  links={[
    { source: "visits", target: "signups", value: 60 },
    { source: "visits", target: "bounced", value: 40 },
    { source: "signups", target: "customers", value: 45 },
    { source: "signups", target: "churned", value: 15 },
  ]}
  stageLabels={["Visits", "Converted", "Outcome"]}
/>
```

## Stage labels aren't derived from node data

`stageLabels` is a separate array (one entry per distinct `stage` value, in ascending order) from any per-node data — Figma's own instance showed non-sequential placeholder numbers ("0, 1, 2, 4") that turned out to be a Figma artifact, not real data, which is why this is a prop you set intentionally rather than something read off the nodes. Omit it for each stage's own number:

## Legend is manual

Unlike bar/line/donut, a link doesn't belong to one obvious "series" the way a bar or line datum does — so `legend` is an explicit array you compose to match however you're coloring `links` (by source node, by outcome, whatever makes sense for the data), rather than something derived automatically.

## Colors

Links default to the five-color `--chart-1`…`--chart-5` palette assigned by index — pass `color` on a link to override that one link.

### One color

Pass `color` on the chart itself (not a link) for a monochrome chart instead of the categorical palette — nodes render at full opacity, ribbons keep the same muted-by-default/full-on-hover split as always, just with one color throughout instead of one per link. A per-link `color` still overrides this for that one link.

```tsx
<SankeyChart nodes={nodes} links={links} color="var(--chart-1)" />
```

## Branching drop-off (hidden nodes)

A node can be `hidden` — it still gets laid out and gives a link a real endpoint, but draws no marker of its own. Pairing a hidden node with a stage that already has a real, visible node splits that stage's incoming flow into two: the part that continues on to the next visible stage, and the part that branches off and ends there instead (attrition, drop-off) — without adding an extra visible stage for it.

```tsx
<SankeyChart
  nodes={[
    { id: "backlog", stage: 0 },
    { id: "assigned", stage: 1 },
    { id: "droppedAfterBacklog", stage: 1, hidden: true },
    // …
  ]}
  links={[
    { source: "backlog", target: "assigned", value: 20 },
    { source: "backlog", target: "droppedAfterBacklog", value: 5 },
    // …
  ]}
  nodeWidth={8}
  stageAlign="centers"
/>
```

## Node width and alignment

`nodeWidth` (default 3) sets each stage marker's thickness in real px, regardless of the chart's own rendered width — drawn as a stroked line (`vector-effect: non-scaling-stroke`, the same technique `<LineChart>` uses for its own line), not a fill shape sized in viewBox units, since only that technique holds an exact px value steady across any container width.

`stageAlign` (`"edges"` default, or `"centers"`) controls where each stage sits horizontally. `"edges"` spreads stages from the chart's own left edge to its right edge, matching Figma. `"centers"` instead splits the width into equal bands (one per stage) and centers each stage within its own band — for lining a Sankey up against a same-width column layout rendered alongside it, like a kanban board, where each stage needs to sit under the middle of its column rather than at a shared edge.

## Tooltip wording

By default a link's tooltip is two lines — `label` (defaults to `"{source} → {target}"`) above the raw `value`. Set `omitTooltipValue` on a link when `label` already reads as a complete sentence with the number folded in (e.g. `"20 moved to assigned"` instead of `"Backlog → Assigned"` + `"20"`) — this hides the redundant second line rather than repeating the number.

## Accessibility

- The ribbons and nodes are decorative markup with no accessible fallback of their own; pair with a visually-hidden data table or summary if the underlying flow data needs to reach assistive tech.
- Stage-label and legend text render as real, readable text.
